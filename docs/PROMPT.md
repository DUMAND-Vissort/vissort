## 1. Что такое Vissort

**Vissort** — веб-платформа для тренировки зрительного анализатора. Работает в браузере. Три задачи:
- Повышение остроты зрения.
- Снятие спазма аккомодации.
- Снятие астенопии (зрительного утомления).

**История:** преемник ColorEyesKeeper (настольная программа). Проект развивается 3 месяца.

**Целевая аудитория:**
- **B2B клиники** — врач назначает, пациент занимается, клиника платит.
- **B2B частные врачи** — ведут практику, продают домашний курс.
- **B2C индивидуалы** — родители, взрослые, прямая подписка.

**Цель проекта:** 100 000 активных постоянных пользователей. Простое добавление фич тренировок. Генератор новых типов сценариев. Минимальная помощь программистов — только основатель.

**Ключевой принцип:** создать ядро системы для дальнейшего увеличения функциональности и масштабируемости **без переделок структуры и архитектуры**.

## 2. Технический стек

**Frontend:**
- Vanilla JS (без фреймворков), HTML, CSS.
- Service Worker для офлайна.
- Web Speech API для голоса.
- face-api.js (TinyFaceDetector, inputSize 320, scoreThreshold 0.25).
- Canvas API для стимулов.

**Backend:**
- Supabase (PostgreSQL + Auth + Edge Functions на Deno).
- RLS (Row Level Security) — 8 таблиц, 17 политик, 4 роли.
- Edge Functions: `generate-scenario` (DeepSeek-прокси), `sentry-proxy`.
- Миграции SQL.

**AI:**
- DeepSeek через Edge Function (rate-limit 20/час на user_id).

**Sentry:** через Supabase-прокси (tunnel key).

**CI/CD:**
- GitHub Actions: 28 Playwright-тестов + ежедневный pg_dump БД.
- Auto-bump SW cache через CI (`[skip ci]`).

**Инфраструктура:**
- Supabase project: `hzvypwdpdhsjzaclxmbm.supabase.co`
- Прод: `vissort.com`
- Репозиторий: `github.com/DUMAND-Vissort/vissort` (приватный)

## 5. Что работает

- Редактор сценариев: граф с 5 типами узлов (STIMULUS, DYNAMIC, READING, LOGIC_IF, COMPARE).
- Плеер: браузер, офлайн-first.
- Камера: face-api, IPD-калибровка, дистанция.
- Устойчивость распознавания: 3 состояния.
- Hard limit дистанции 1.0 м + баннер.
- Rate-limit AI-генератора (20/час).
- Офлайн-режим (SW + IndexedDB + syncQueue).
- Калибровка: 2 шага (PPI + камера).
- Синхронизация калибровки: по fingerprint+userId.
- Моргание: детекция через EAR.
- Кнопка 📐 — повторная калибровка.
- Роли: admin, developer, doctor, patient.
- VissortDialog, VissortLog, VissortEnv.

**Инфраструктура:**
- Supabase: Auth, RLS, Edge Functions, миграции.
- RLS: 8 таблиц, 17 политик.
- Edge Functions: CORS, retry, timeout 60s.
- Автобэкап: GitHub Actions, pg_dump 17.
- CI: 28 Playwright-тестов + backup-db.
- schemaVersion: 2 + migrateScenario.

## 8. Принципы работы (обязательны)

1. **Прод не ломаем.** Каждое изменение — отдельный коммит.
2. **После правок — тесты:** `npx playwright test --reporter=list` (28 тестов).
3. **Никаких новых PATCH* комментариев.**
4. **Один коммит = одна задача.**
5. **Перед push — `git status` и `git diff` глазами.**
6. **Кириллица: UTF-8 без BOM.**
7. **Файл заблокирован** → `.tmp` + `Move-Item -Force`.
8. **Порядок загрузки:** `vissort-logger.js` → `vissort-env.js` → `vissort-dialog.js` → `vissort-core.js` → модули.
9. **Тонкие обёртки — не модули.** Если функция = одна строка `return window.X.y()` — не выносить.
10. **Регионы объявлений разбирать построчно.** Regex `^\s*(let|var|const)` не ловит продолжения через запятую.

## 9. Антипаттерны

**Технически:**
- Не загружать `vissort-logger.js` после `vissort-env.js` — VLog не определён.
- Не рефакторить `player-runtime.js` без тестов.
- Не менять структуру сценариев без schemaVersion.
- Не патчить `admin.html` через PowerShell here-string (кириллица ломается).
- Не пушить в прод в пятницу вечером.
- Не удалять PATCH* комментарии без замены.
- Не вызывать `Set-Content` на файл без `.tmp` + `Move-Item`.
- Не менять RLS-политики без теста утечки.
- Не редактировать Edge Functions без `npx supabase functions deploy`.
- **Не использовать here-string `@'...'@` для длинных текстов с кириллицей в PS 7.6.6 — зависает.**
- **`node --check` не понимает `.tmp`** — копировать в `.js` перед проверкой.
- **`WriteAllText` может упасть в PS 7.6.6 на больших скриптах** — обход через `.tmp` + `Move-Item`.
- **`vissort-dialog.js`** — `showModal()` не ставит `[open]` → `setAttribute('open', '')` для тестов.

**Продуктово:**
- Не обещать излечения.
- Не делать публичные рейтинги.
- Не продавать клиникам до пилота.
- Не идти к федеральным клиникам без медизделия.

**В работе с ассистентом:**
- Не просить сделать всё сразу.
- Не пересказывать контекст — он уже здесь.
- Не молчать, если что-то не работает — показать ошибку.

## 10. Формат работы с тобой (ИИ-ассистентом)

**Что ты делаешь:**
- Даёшь PowerShell-команды для правок.
- Пишешь SQL-миграции, HTML, CSS, документацию, JS-модули.
- Диагностируешь ошибки по выводу команд.

**Что ты НЕ делаешь:**
- Не имеешь доступа к интернету, не запускаешь код, не видишь файлы.
- Не создаёшь файлы сам — только через команды пользователя.
- Не работаешь с чувствительными ключами.

**Что нужно от пользователя:**
- Точные выводы команд (не пересказ).
- Скриншоты, если проблема визуальная.
- Если патч — сказать, применился или нет, показать `node --check` и `Select-String`.
- Если ошибка — первый красный текст из Console.

**Стиль ответа:**
- Максимальная плотность.
- Одна мысль — одна строка.
- Один путь, а не три.
- **Формат:** Заголовок → патч / команда → проверка → что скинуть. Без преамбул.
