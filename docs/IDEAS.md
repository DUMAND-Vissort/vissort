## 2026-10-17 — Тренинг «Найди вживую» (перцептивное соотнесение экран ↔ реальность)

### Идея
На экране транслируется фрагмент вида комнаты или вида за окном. Пациент смотрит на элемент на экране — затем находит этот элемент вживую, вне экрана.

### Механика
1. Камера делает снимок комнаты / вида за окном.
2. Из снимка вырезается фрагмент (объект, деталь, текстура).
3. Фрагмент показывается на экране (например, 3–5 секунд).
4. Пациент отводит взгляд от экрана и ищет этот элемент в реальной комнате.
5. Подтверждение: кнопка «нашёл» / «не нашёл» / «подсказка».
6. Адаптивная сложность: размер фрагмента, время показа, дистанция до объекта.

### Что тренирует
- Зрительное внимание и поиск.
- Сличение образа из памяти с реальностью.
- Периферийное зрение (поиск без прямого наведения).
- Пространственную ориентацию.
- Произвольное переключение аккомодации (экран → реальность → экран).

### Техническая реализуемость
- **Камера:** уже есть (`face-api.js`, `player-camera.js`).
- **Снимок → фрагмент:** canvas + crop по координатам.
- **Показ фрагмента:** новый тип сценария (например, `FIND_REAL`).
- **Подтверждение:** кнопки в UI плеера.
- **Калибровка (PPI, дистанция):** уже есть.
- **Новый модуль плеера:** `player-find-real.js` (~300–500 строк).

### Открытые вопросы
- Как валидировать «нашёл / не нашёл» без участия методиста?
- Нужен ли второй человек (родитель / врач) для подтверждения?
- Как избежать читерства (пациент просто угадывает)?
- Работает ли тренинг на улице / в незнакомой комнате?
- Как масштабировать: библиотека «фрагментов» или всегда live-снимок?

### Приоритет
**Средний.** Идея сильная, но требует:
- Новый тип сценария.
- Новый модуль плеера.
- UI подтверждения.
- Возможно — второй человек для валидации.

Реализовать после Фазы 5 (завершение рефакторинга `app.js`).

## 2026-10-17 — Универсальный экспресс-тест «Индекс Зрительного Ресурса»

### Идея
Экспресс-тест состояния зрения за 1–2 минуты. Не требует медицинского оборудования. Использует веб-камеру + интерактивные механики. Определяет не диоптрии, а функциональное состояние зрительной системы прямо сейчас: спазм, координацию, утомление.

### Архитектура (4 субтеста последовательно)

1. **Динамическая аккомодация.** Контрастный объект (кольцо) плавно уменьшается/увеличивается. Пользователь моргает или жмёт пробел, когда контуры двоятся. Измеряет порог фиксации фокуса и зажатость цилиарной мышцы.

2. **Тест Шульте-Vissort.** Взгляд на центральной точке. На периферии вспыхивают сигналы. Задача — заметить боковым зрением, нажать стрелку. Измеряет сужение периферического обзора.

3. **Глазодвигательный трекинг.** Веб-камера калибруется по зрачкам. По экрану движется маркер по сложной траектории. Пользователь следит глазами. Измеряет симметричность и плавность работы 6 мышц, микро-саккады.

4. **Астигматизм и зрительный шум.** На 5 секунд — лучистая звезда или двухцветный фон. Пользователь оценивает чёткость. Измеряет оптические искажения.

### Результат — «Индекс Зрительного Ресурса» (Score)
Вместо медицинских терминов — понятный интегральный показатель в процентах.

### Почему идеален для мотивации
- **Наглядность:** деградация зрения в течение дня (утром 95%, к обеду 45%).
- **Мгновенный пруф (До/После):** тест 1 мин → 45% → тренировка 4 мин → тест → 85%. Дофамин + привычка.

### Техническая реализуемость
- Камера: face-api.js, player-camera.js (есть).
- Трекинг зрачков: новый модуль (face-api даёт landmarks, не зрачки).
- 4 субтеста: player-express-test.js.
- Score: калькулятор по 4 метрикам.
- Онбординг: объяснение до/после.

### Открытые вопросы
- Точность калибровки зрачков через face-api — достаточно?
- Валидация Score против клиники (пилот).
- Блокировка экрана — навязчиво или мягко?
- Онбординг: при первом входе или опционально?

### Приоритет
**Высокий.** Точка входа в продукт + сильный мотиватор. После Фазы 5.
